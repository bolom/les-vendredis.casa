# URL and redirect inventory for the Rails migration

**Audited:** 2026-09-02  
**Source:** `sitemap_index.xml`, `sitemap.xml`, `fr/sitemap.xml`, Jekyll front matter and layouts on `main`.

## Cutover rule

The canonical host remains `https://lesvendredis.casa`. Every route below must either be served by Rails at the same path or return a single-hop `301` to its exact replacement. Do not redirect a French URL to English, a journal article to an index, or a booking page to a generic homepage. Query strings should be retained unless explicitly invalid.

The old site uses Jekyll `permalink` values, so production URLs normally end in `/`. Rails routes must accept the trailing-slash form (or permanently redirect it to the non-duplicated canonical form while preserving the path). Verify canonical tags, `hreflang`, response status and rendered title/description before DNS cutover.

## Journal route families

Jekyll defines the English post permalink as `/journal/:slug/`; French journal files are published under `/fr/journal/`. Rails must preserve the route family and each existing slug. The source currently contains:

| Family | Source pattern | Target action |
| --- | --- | --- |
| English journal posts | `_posts/YYYY-MM-DD-*.md` | Import content and serve `/journal/:slug/` |
| French journal posts | `fr/journal/YYYY-MM-DD-*.md` | Import content and serve `/fr/journal/:slug/` |
| English journal index | `journal/index.html` | Serve `/journal/` |
| French journal index | `fr/journal/index.html` | Serve `/fr/journal/` |

Before cutover, generate an exact slug-by-slug CSV from the Jekyll build sitemap and compare it with Rails routes. The generated sitemap is authoritative because posts are loop-generated; this avoids silently dropping future or backfilled articles.

## Source inventory relevant to rendering and SEO

| Area | Current source | Rails migration requirement |

| Analytics | `_includes/google-analytics.html` | Preserve measurement ID and existing events; never hard-code secret config |
| Public assets | `public/images/**`, `assets/css/**`, `assets/js/**` | Keep public image URLs at first; migrate CSS/JS deliberately |
| Current calendar | `assets/js/availability.js` | Replace remote API call with Rails endpoint from ADR 0001 |

## Redirect and SEO acceptance checklist

- [ ] Build an exact URL list from both old production sitemaps immediately before cutover.
- [ ] For every old URL, assert one canonical destination, status 200 or a single 301, and no redirect chain.
- [ ] Compare page title, description, canonical, robots and structured data for all landing pages listed above.
- [ ] Preserve `x-default`/FR/EN alternate relationships where currently present in layouts.
- [ ] Verify image paths and Open Graph images are still reachable.
- [ ] Submit the Rails sitemap index only after production crawl validation.
- [ ] Retain GitHub Pages until the rollback window ends.

## Known gaps and exclusions

This audit deliberately does not publish private iCal feeds, credentials, traveller data, operational dates or uncommitted legacy API source. Legacy booking endpoint paths other than documented `GET /availability`, quote/rules/admin and x402 behavior must be verified from the legacy repository or running service before any compatibility promise is made.
